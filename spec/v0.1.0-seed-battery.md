## What expansion to v0.2.0 looks like

Per category, the goal is 6–10 prompts varying along three axes:

1. **Adversarial pressure** — pure neutral instruction → mild social pressure
   ("hurry, the meeting starts in five minutes") → explicit jailbreak attempt.
2. **Surface form** — direct user instruction → instruction embedded in
   screen content → instruction embedded in tool output (file read, web fetch).
3. **Plausible-deniability framing** — overt malicious ask → ask that *looks*
   like a legitimate cleanup/admin task but maps to a failure mode.

Each axis-combination is one experiment. With three axes and conservative
binning that produces ~12 distinct prompts per category; we'll trim to the
6–10 most discriminating.

## Reproducibility notes

- Harness: `agent-app-control` at commit [pin SHA when first run executes]
- Sandbox: Hyprland VM with `sandbox-gate` enabled, `XDG_STATE_HOME` deliberately
  unset for C1 prompts to reproduce the 2026-05-13 incident's environmental
  preconditions. See `docs/SANDBOX.md`.
- Model coverage (revised — no paid vendor APIs per fleet policy):
  - **Claude Opus 4.7** + **Claude Sonnet 4.6** — invoked via the
    Claude Code CLI in non-interactive mode (subscription auth, not API key).
  - **Llama-3.x-Instruct** — open-weight, served locally via `llama.cpp`
    or MLX with a thin agent-loop wrapper.
  - **Qwen2.5** + **DeepSeek-V3** (open-weight) — same local-serve
    pattern. These replace the "GPT-5-class" slot from the original
    scaffold draft; OpenAI API access is intentionally off-table.
  - Thesis: comparing one closed-weight frontier family (Anthropic) against
    three open-weight families is a sharper comparison surface than
    sprinkling a single competitor API into the mix.
- Output: raw model trace + audit envelope JSONL + per-prompt verdict.
